# ระบบปฏิทินการปฏิบัติงาน (Real-time Cloud System)

เว็บแอปพลิเคชันระบบปฏิทินและกำหนดการปฏิบัติงานสำหรับองค์กร/สถาบัน ข้อมูลเป็น **Real-time ซิงก์ร่วมกันได้ทุกเครื่องทันที** รองรับการใช้งานพร้อมกันหลายอุปกรณ์ ภาษาไทยทั้งระบบ แสดงผลปีเป็น **พ.ศ.** รองรับมือถือ (Mobile-First) และโหมดมืด (Dark Mode)

---

## 🏗️ สถาปัตยกรรมระบบ (System Architecture)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        ผู้ใช้งาน / Client Devices                     │
│   (Browser 1: มือถือ)      (Browser 2: คอมพิวเตอร์)     (Browser 3: แท็บเล็ต)  │
└────────────▲────────────────────────▲────────────────────────▲─────────┘
             │                        │                        │
             │   WebSocket Real-time  │  (onSnapshot)          │
             ▼                        ▼                        ▼
┌────────────────────────────────────────────────────────────────────────┐
│               ฐานข้อมูลหลัก: Firebase Firestore Database              │
│  - Collection "events": เก็บรายการงานและสถานะ พร้อม real-time sync     │
│  - Collection "users": เก็บบทบาท (admin, head, staff) และแผนกสังกัด    │
│  - Collection "holidays": เก็บวันหยุดราชการ/องค์กร                     │
│  - Security Rules: ควบคุมสิทธิ์การเข้าถึงข้อมูลตามบทบาทผู้ใช้          │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                         Background Sync / On-demand
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│              ฐานข้อมูลสำรอง & รายงาน: Google Sheets Database           │
│  - ชีต "Events" (คอลัมน์: id, title, type, status, assignee, start,   │
│                 end, startTime, endTime, location, detail, updatedAt)  │
│  - ชีต "Users" & "Holidays"                                           │
│  - Email Reminder Trigger: ส่งอีเมลแจ้งเตือนทุกเช้า 08:00 น.           │
│  - Google Apps Script Web App: JSON API รองรับการ Upsert & Import      │
└────────────────────────────────────────────────────────────────────────┘
```

1. **ฐานข้อมูลหลัก (Primary DB):** Firebase Firestore
   - ใช้ `onSnapshot` เพื่อฟังการเปลี่ยนแปลงของ Collection `events` แบบ Real-time ทุกเครื่องจะเห็นการเพิ่ม แก้ไข หรือลบงานทันทีโดยไม่ต้องกดรีเฟรชหน้าจอ
   - ระบบ **Optimistic Update**: หน้าจอจะปรับเปลี่ยนทันทีที่ผู้ใช้กดบันทึกหรือเปลี่ยนสถานะงาน พร้อมแจ้งเตือน Rollback ทันทีหากเกิดข้อผิดพลาดในการบันทึก
   - ระบบ **Concurrent Edit Protection**: ตรวจสอบกรณีที่มีผู้ใช้กำลังแก้ไขงานเดียวกันพร้อมกัน โดยจะแสดงแถบแจ้งเตือนและยึดข้อมูลล่าสุดจากระบบเป็นหลัก
   - ไม่ใช้ `localStorage` เป็นแหล่งข้อมูลหลัก (ใช้เฉพาะออฟไลน์แคชชั่วคราว)

2. **ระบบยืนยันตัวตน (Authentication):**
   - Firebase Authentication (Google Sign-In) ดึงสิทธิ์ของผู้ใช้จาก Collection `users` (`admin` / `head` / `staff`)

3. **ฐานข้อมูลคู่ขนานและการสำรอง (Secondary DB):** Google Sheets
   - เมื่อมีการสร้าง แก้ไข หรือเปลี่ยนสถานะงานใน Firestore ระบบจะซิงก์ข้อมูลไปอัปเดตแถวในชีต `Events` ตาม `id` พร้อมบันทึกเวลา `updatedAt` อัตโนมัติ
   - มีปุ่ม **"นำเข้าจาก Google Sheets"** สำหรับ Admin เพื่ออ่านข้อมูลจากชีตแล้ว Upsert เข้าสู่ Firestore

## 🛠️ ขั้นตอนการติดตั้งและตั้งค่าทีละขั้น (Step-by-Step Setup)

### ขั้นตอนที่ 1: ตั้งค่า Firebase Project (Firestore & Authentication)

1. ไปที่ [Firebase Console](https://console.firebase.google.com/) แล้วคลิก **"Add project"** (เพิ่มโปรเจกต์)
2. ตั้งชื่อโปรเจกต์ เช่น `work-calendar-system` แล้วคลิก Continue จนสร้างโปรเจกต์เสร็จสิ้น
3. **เปิดใช้งาน Authentication:**
   - เมนูด้านซ้ายเลือก **Build → Authentication**
   - คลิกปุ่ม **Get started**
   - ที่แท็บ **Sign-in method** ให้เลือก **Google** → กด **Enable** → เลือกอีเมลฝ่ายสนับสนุนของโปรเจกต์ → กด **Save**
4. **เปิดใช้งาน Cloud Firestore:**
   - เมนูด้านซ้ายเลือก **Build → Firestore Database**
   - คลิกปุ่ม **Create database**
   - เลือก Location ใกล้เคียง (เช่น `asia-southeast1` สิงคโปร์)
   - เลือกเริ่มต้นด้วย **Production mode** (โหมดการใช้งานจริง) → กด Create
5. **ติดตั้ง Firestore Security Rules:**
   - ในหน้า Firestore ให้คลิกแท็บ **Rules** ด้านบน
   - นำโค้ดทั้งหมดจากไฟล์ `firestore.rules` ในโปรเจกต์นี้ไปวางแทนที่ของเดิม
   - คลิกปุ่ม **Publish** (เผยแพร่)
6. **คัดลอก Firebase Config:**
   - คลิกไอคอนรูปฟันเฟือง ⚙️ ข้าง Project Overview (มุมซ้ายบน) → เลือก **Project settings**
   - เลื่อนลงมาที่หัวข้อ **Your apps** → คลิกไอคอนเว็บ `</>`
   - ตั้งชื่อเล่นแอป เช่น `Work Calendar Web` → คลิก **Register app**
   - คัดลอกเฉพาะก้อน JavaScript Object ใน `firebaseConfig`:
     ```json
     {
       "apiKey": "AIzaSy...",
       "authDomain": "your-project.firebaseapp.com",
       "projectId": "your-project-id",
       "storageBucket": "your-project.appspot.com",
       "messagingSenderId": "...",
       "appId": "..."
     }
     ```

### ขั้นตอนที่ 2: ตั้งค่า Google Sheets & Apps Script

1. ไปที่ [Google Sheets](https://sheets.google.com) แล้วสร้าง Spreadsheet ใหม่ ตั้งชื่อว่า **"ระบบปฏิทินการปฏิบัติงาน"**
2. คลิกเมนู **ส่วนขยาย (Extensions) → Apps Script**
3. ลบโค้ดเดิมทั้งหมดใน `Code.gs` ออก แล้วนำโค้ดจากไฟล์ `Code.gs` ในโปรเจกต์นี้ไปวางแทนที่
4. กดปุ่ม **บันทึก (Ctrl+S)**
5. **สร้างข้อมูลตัวอย่างในชีต:**
   - ที่แถบเครื่องมือด้านบน เลือกฟังก์ชัน `initSampleData` แล้วคลิก **เรียกใช้ (Run)**
   - กดยอมรับสิทธิ์การเข้าถึง (Review permissions → Advanced → Go to unsafe → Allow)
   - ชีตจะถูกสร้าง 3 ชีตพร้อมข้อมูลตัวอย่าง: `Events`, `Users`, `Holidays`
6. **ตั้งค่า Email Trigger:**
   - เลือกฟังก์ชัน `setupTrigger` แล้วคลิก **เรียกใช้ (Run)** เพื่อเปิดระบบส่งอีเมลแจ้งเตือนทุกเช้า 08:00 น.
7. **Deploy เป็น Web App:**
   - คลิก **ทำให้ใช้งานได้ (Deploy) → การทำให้ใช้งานได้รายการใหม่ (New deployment)**
   - เลือกประเภทเป็น **เว็บแอป (Web app)**
   - ตั้งค่า:
     - ดำเนินการในฐานะ: **ฉัน (Me)**
     - ผู้ที่มีสิทธิ์เข้าถึง: **ทุกคน (Anyone)**
   - คลิก **ทำให้ใช้งานได้ (Deploy)**
   - คัดลอก **URL เว็บแอป (Web App URL)** ที่ลงท้ายด้วย `/exec` เก็บไว้

### ขั้นตอนที่ 3: ผูกการตั้งค่าเข้ากับหน้าเว็บ Frontend

1. เปิดไฟล์ `index.html` ในเบราว์เซอร์ (หรือเข้าผ่าน GitHub Pages)
2. เข้าสู่ระบบ (สามารถเลือกบัญชีทดสอบเพื่อเข้าไปก่อนได้)
3. คลิกปุ่มฟันเฟือง **⚙️** บน Header ด้านบนขวา
4. **วาง Firebase Config JSON** ที่ได้จากขั้นตอนที่ 1 ลงในช่องแรก
5. **วาง Google Apps Script Web App URL** ที่ได้จากขั้นตอนที่ 2 ลงในช่องที่สอง
6. คลิก **"💾 บันทึกการตั้งค่า"**
7. สังเกตสถานะใต้หัวข้อจะเปลี่ยนเป็น **🟢 เรียลไทม์** ทันที!

## 🧪 วิธีทดสอบการทำงาน Real-time ด้วย 2 เบราว์เซอร์พร้อมกัน

เพื่อให้มั่นใจว่าระบบซิงก์ข้อมูลระหว่างเครื่องอย่างสมบูรณ์แบบ ให้ทำการทดสอบดังนี้:

```
┌─────────────────────────────────┐       ┌─────────────────────────────────┐
│     หน้าต่างที่ 1: Google Chrome    │       │     หน้าต่างที่ 2: Microsoft Edge │
│       (หรือโหมดปกติ)              │       │       (หรือหน้าต่างไม่ระบุตัวตน)  │
├─────────────────────────────────┤       ├─────────────────────────────────┤
│ 👤 ผู้ใช้: นายสมชาย (Staff IT)    │       │ 👤 ผู้ใช้: หัวหน้าฝ่าย IT (Head)  │
│                                 │       │                                 │
│ 1. กดปุ่ม "+ เพิ่มงาน"           │       │ 2. เห็นงานปรากฏขึ้นบนปฏิทิน     │
│    พิมพ์ชื่องาน: "ทดสอบซิงก์สด"   │──────▶│    ทันทีโดยไม่ต้องกดรีเฟรช!     │
│    กดบันทึก                     │       │                                 │
│                                 │       │ 3. กดเปลี่ยนสถานะงานนั้น        │
│ 4. สถานะงานเปลี่ยนเป็น "เสร็จแล้ว" │◀──────│    เป็น "เสร็จแล้ว"             │
│    บนหน้าจอทันที!               │       │                                 │
└─────────────────────────────────┘       └─────────────────────────────────┘
```

### 1. ทดสอบการเพิ่มและเปลี่ยนสถานะงานแบบ Real-time:
1. เปิดหน้าเว็บใน **Browser 1** (เช่น Chrome) และ **Browser 2** (เช่น Edge หรือ Incognito) วางไว้ข้างกันบนหน้าจอ
2. ที่ **Browser 1**: กดปุ่ม **"+ เพิ่มงาน"** กรอกชื่องานแล้วกด **บันทึก**
3. **ผลลัพธ์:** ที่ **Browser 2** จะเห็นแถบงานใหม่ปรากฏขึ้นบนปฏิทินทันทีในเสี้ยววินาที โดยไม่ต้องกดรีเฟรชหน้าจอ
4. ที่ **Browser 2**: คลิกที่งานนั้นแล้วกดปุ่มเปลี่ยนสถานะเป็น **"เสร็จแล้ว"**
5. **ผลลัพธ์:** ที่ **Browser 1** งานนั้นจะถูกขีดฆ่าและเปลี่ยนสถานะเป็นเสร็จแล้วในทันที

### 2. ทดสอบระบบป้องกันการแก้ไขพร้อมกัน (Concurrent Edit Detection):
1. เปิดหน้าแก้ไข (Edit Modal) ของ **งานเดียวกัน** ไว้ทั้ง 2 Browser พร้อมกัน
2. ที่ **Browser 1**: แก้ไขชื่องานแล้วกด **"บันทึก"**
3. **ผลลัพธ์:** ที่ **Browser 2** ซึ่งเปิดค้างไว้อยู่ จะแสดงแถบสีส้มแจ้งเตือนทันที:
   > *"⚠️ ตรวจพบการแก้ไขจากเครื่องอื่น: ระบบได้อัปเดตข้อมูลเป็นเวอร์ชันล่าสุดเรียบร้อยแล้ว"*
   และข้อมูลในช่องกรอกจะปรับเป็นค่าใหม่ล่าสุดอัตโนมัติ ป้องกันการบันทึกทับข้อมูลเก่า

### 3. ทดสอบการซิงก์ลง Google Sheets:
1. เมื่อมีการเพิ่มหรือแก้ไขงานในหน้าเว็บ ให้เปิดดูที่ Google Spreadsheet ในชีต **Events**
2. ข้อมูลงานจะถูกเขียนลงแถวใน Google Sheets พร้อมคอลัมน์ `updatedAt` แสดงเวลาแก้ไขล่าสุด

### 4. ทดสอบปุ่ม "นำเข้าจาก Google Sheets":
1. ลองแก้ไขข้อมูลในแถวของชีต **Events** ใน Google Sheets โดยตรง
2. ที่หน้าเว็บ ล็อกอินด้วยบัญชี **Admin** → คลิกเมนู **"นำเข้าจากชีต"**
3. ข้อมูลใน Google Sheets ทั้งหมดจะถูกอ่านและ Upsert เข้าสู่ Firestore ทันที

## 🔒 กฎความปลอดภัย Firestore (Security Rules Explained)

ไฟล์ `firestore.rules` มีการแบ่งสิทธิ์ตามหลัก RBAC ดังนี้:

| บทบาท (Role) | การดูปฏิทิน (Read) | การสร้างงาน (Create) | การแก้ไข/ลบงาน (Update/Delete) |
|:---:|:---:|:---|:---|
| 🧑‍💻 **Staff** | ดูงานทั้งหมดได้ | สร้างงานให้ตนเองได้ | แก้ไขและลบได้**เฉพาะงานที่ตนเองเป็นผู้รับผิดชอบ** (`assignee`) |
| 👔 **Head** | ดูงานทั้งหมดได้ | สร้างงานได้ | แก้ไขและลบงานของ**สมาชิกในแผนกเดียวกัน**ได้ |
| 👑 **Admin** | ดูงานทั้งหมดได้ | สร้างงานได้ทุกประเภท | จัดการได้**ทุกงาน ทุกแผนก** รวมทั้งจัดการผู้ใช้และวันหยุด |

## 🌐 การนำขึ้น GitHub Pages

โปรเจกต์นี้พัฒนาเป็น Static Web App (HTML/CSS/JS) พร้อมทำงานบน GitHub Pages ได้ทันที:

1. Push โค้ดทั้งหมดขึ้น GitHub Repository:
   ```bash
   git add .
   git commit -m "Update: Real-time Firestore & Sheets Sync"
   git push origin main
   ```
2. ไปที่หน้า GitHub Repository → **Settings → Pages**
3. เลือก Source เป็น `Deploy from a branch` → เลือก Branch `main` และโฟลเดอร์ `/ (root)` → กด **Save**
4. เปิดใช้งานเว็บผ่านลิงก์ `https://<USERNAME>.github.io/<REPO_NAME>/` ได้ทันที ทุกเครื่องจะเชื่อมต่อฐานข้อมูลเดียวกันผ่าน Firebase และ Google Sheets ครับ
